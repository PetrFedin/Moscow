# Pilot Evidence Archive Structure

## Purpose

Define one reproducible archive for all evidence generated by the Varvarka/Zaryadye controlled pilot.

This structure does not create evidence. It only makes real evidence attributable, reviewable and hashable.

## Root

`evidence/varvarka-zaryadye/<pilot-run-id>/`

Recommended:

```
00-governance/
01-build/
02-romanov/
03-old-english-court/
04-visitor-pilot/
05-provider/
06-observability/
07-economics/
08-acceptance/
09-final/
```

## 00-governance

- owner-assignment.json
- approved-scope-ref.txt
- acceptance-matrix-ref.txt
- site-access-ref.txt
- security-review-ref.txt
- legal-rights-review-ref.txt
- operations-sla-review-ref.txt

## 01-build

- frozen-build-ref.txt
- package/model checksums
- supported-device matrix
- build notes

## 02-romanov

- campaign/survey package
- per-device session bundles
- residual evidence
- persistent-anchor proof
- optional AprilTag auxiliary calibration evidence
- validator output
- reviewer decision

AprilTag evidence is **auxiliary only** and cannot promote Romanov PASS.

## 03-old-english-court

Independent object-specific:

- model evidence
- metric/control-point authority
- survey
- field matrix
- persistent-anchor evidence
- repeatability proof
- reviewer decision

Romanov evidence must not be reused as OEC authority.

## 04-visitor-pilot

- study-manifest.json
- reports/
- observers/
- final-study-report.json
- review outcome

Recruitment/consent files, if required, must remain outside app analytics and be stored according to the agreed privacy process.

## 05-provider

- real API raw response
- SHA-256
- admission evidence
- controlled record reference
- webhook raw/normalized evidence
- state-change evidence
- Journey Runtime audit
- terminal provider receipt
- Journey Evidence Pack
- provider proof result

Receiver one-shot evidence must be archived immediately.

## 06-observability

Operational diagnostics only:

- Sentry configuration/review reference
- bounded incident exports if used
- incident IDs / remediation notes

Never treat Sentry events as spatial/product acceptance evidence.

## 07-economics

- production cost records
- time logs
- integration work package
- operator-hours evidence
- reconciliation note
- validated economics capture

## 08-acceptance

- acceptance matrix
- deviations/change log
- reviewer decisions
- blocked criteria

## 09-final

- Phase 0 evidence manifest
- final pilot report
- scale/no-scale decision record
- immutable archive index

## Integrity rules

- no placeholder PASS artifacts;
- no synthetic raw provider receipts;
- no edited field measurement after review;
- every final evidence ref must point to a real archived artifact;
- hashes prove integrity, not honesty of physical measurement;
- signed Destination Package remains Phase 1 and must not be fabricated for Phase 0.
