# AR / 3D / VR — техническое направление

## Принцип

AR, 3D и VR — не декоративные разделы. Они используются только там, где помогают понять изменение места и где качество сцены можно проверить.

## AR на улице

Целевой сценарий:

1. Пользователь подходит к подготовленной точке обзора.
2. Приложение определяет объект и предлагает открыть AR.
3. Сцена совмещается с реальным пространством.
4. Пользователь переключает исторические состояния.
5. При потере привязки приложение восстанавливает сцену или предлагает ручное уточнение.
6. При недостаточной точности доступен архивный режим сравнения вместо ложного «точного AR».

### Требования к первой сцене

- модель в реальном масштабе;
- заданная система координат и точка наблюдения;
- мобильная оптимизация геометрии и текстур;
- устойчивое повторное открытие;
- контроль ошибки совмещения;
- безопасное положение пользователя на улице;
- fallback при плохом трекинге;
- отметка степени исторической достоверности.

## 3D

Одна подготовленная модель должна использоваться повторно:

- интерактивный просмотр в карточке места;
- AR на улице;
- VR-сцена;
- образовательный режим;
- презентационный режим для городского пилота.

Модель разделяется на смысловые слои: объём, фасад, элементы, доказанные состояния и реконструированные детали.

## VR

Первый VR-эпизод должен быть коротким и законченным, а не «виртуальным музеем всего города».

Сценарий пилота:

- вход в историческую сцену Варварки;
- переход между двумя подтверждёнными состояниями;
- несколько интерактивных объектов;
- пространственный звук;
- объяснение источников и реконструкции;
- режим без свободного перемещения для пользователей, чувствительных к VR.

## Контентная модель сцены

`place -> historical state -> scene -> scene object -> evidence`

Каждый видимый исторический элемент должен иметь статус:

- documented;
- reconstructed;
- hypothesis;
- artistic.

## Полевые тесты

AR-сцена не считается готовой после проверки в редакторе или видео-демонстрации. Обязательна проверка:

- на поддерживаемых iPhone и Android;
- в ярком и слабом свете;
- при частичном перекрытии объекта;
- после сворачивания приложения;
- после потери трекинга;
- с плохим мобильным интернетом;
- в офлайн-сценарии, если он заявлен.

## Первый приоритет

Палаты бояр Романовых — первая кандидатная сцена для разработки, при условии достаточности исходных материалов и подтверждения точки привязки на месте.
