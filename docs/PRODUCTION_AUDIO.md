# Varvarka production audio authority

Status: **recorded-human-first runtime implemented; 10 RU/EN scripts approved for recording; no human master is claimed as production-ready yet**.

## Product rule

Device TTS is a resilience fallback, not the cultural product.

A tourist should be able to understand whether they are hearing:

- `HUMAN MASTER · VERIFIED` — an approved recorded master;
- `TTS FALLBACK · RECORDING PENDING` — the approved transcript spoken by the device because a verified master does not yet exist or cannot be loaded.

The UI must never label TTS as finished production narration.

## Catalog scope

Five Varvarka stops × two locales:

1. Church of St Barbara — RU / EN.
2. Old English Court — RU / EN.
3. Romanov Chambers — RU / EN.
4. Znamensky Cathedral — RU / EN.
5. Varvarsky Gates — RU / EN.

Each catalog entry owns:

- stable track id and version;
- place id and locale;
- approved transcript;
- target duration;
- source URLs supporting the historical script;
- production status.

## Production master gate

A track can become `production-ready` only when all of the following exist:

- HTTPS master URL;
- safe offline filename;
- SHA-256 of the exact binary master;
- measured duration;
- narrator credit;
- rights evidence reference;
- non-empty approved transcript and source set.

Missing any field means the runtime remains fail-closed on TTS fallback.

## Playback behavior

The walk companion uses the production audio plan as authority:

1. If an authoritative human master exists, `expo-audio` loads it.
2. Playback status is observed through the player event API.
3. On successful finish the tourist stop may complete.
4. On master load/playback error the same approved transcript falls back to device TTS.
5. A manual stop, screen unmount or route interruption is **not** a completed stop.
6. Player/subscription resources are released during stop/error/finish cleanup.

The existing Romanov 3D hotspot voice remains TTS-only until hotspot masters receive the same authority treatment.

## Background playback authority

Human masters are configured for sustained background playback rather than foreground-only demo playback.

- `expo-audio` background playback is enabled in native app configuration;
- Android media-playback foreground-service support is generated by the config plugin;
- iOS receives the audio background mode;
- lock-screen metadata is attached only to a verified recorded master;
- recording capabilities and microphone permissions are explicitly disabled because the guide does not record the tourist.

Runtime audio-session configuration alone is not considered sufficient evidence: the native config is protected by a contract test.

## Transcript

Every Varvarka walk narration exposes its full transcript on the stop card. The transcript is available even when playback is still TTS fallback.

This provides:

- accessibility without depending on audio output;
- auditable script-to-source review;
- a stable text authority for recorded-master QA.

## Offline behavior

The route pack includes the versioned audio catalog immediately.

Actual audio binaries enter the offline pack only after they pass `production-ready`. Pending recordings are never downloaded or counted as available audio.

Every production audio file carries its catalog SHA-256 into the route-pack manifest. The mobile downloader verifies the downloaded bytes before marking the pack ready, and re-checks hashed assets before returning a local URI. A mismatch fails closed instead of serving an unverified master.

## Recording handoff

The next physical/editorial step is to record the ten v1 scripts.

For every returned master capture:

- narrator;
- recording/editing date;
- final codec/container;
- measured duration;
- rights/release document reference;
- final HTTPS delivery URL;
- final filename;
- SHA-256.

Only then update the corresponding catalog item from `recording-pending` to `production-ready`.

No synthetic voice file should be committed merely to turn the gate green.
