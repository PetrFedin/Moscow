# Partner / Investor Data Room

## Purpose

The in-app Data Room answers a practical question after the 7–10 minute Government / Investor Route:

> **what can we actually send and defend for this audience today, and what is still blocked by missing evidence?**

It does not use one generic project-readiness percentage.

Every audience is tied to a different decision and therefore to a different formal package.

## 1. Moscow executive meeting

Decision:

> agree the problem owner, pilot site and a working session on scope / methodology / integration / acceptance.

Package:

- executive one-pager;
- CITY PILOT demo;
- pilot positioning;
- pilot methodology;
- acceptance matrix;
- funding / scale playbook.

Current state:

**READY at repository/content level.**

This does not mean:

- the pilot is approved;
- financing is approved;
- a final buyer or budget owner is known.

## 2. Moscow technical / procurement working session

Decision:

> agree the bounded technical scope, data/integration boundaries, IP/handover, operations and formal acceptance route.

Package:

- executive one-pager;
- consolidated technical specification;
- buyer-facing architecture / integration;
- security / data-flow note;
- IP / rights / handover matrix;
- operations / SLA draft;
- pilot acceptance matrix.

Current state:

**READY at repository/content level.**

This means the project can enter buyer IT/security/legal/procurement review.

It does not mean those external reviewers have approved it.

## 3. Investor scale room

Decision:

> after proof and measured economics, decide whether to finance repeatable production and regional scale.

Package:

- investment-decision authority;
- cost / scale model;
- funding / scale playbook;
- final report structure.

Current state:

**BLOCKED.**

The blocker is not missing marketing copy.

The blocker is real evidence:

- Romanov physical proof;
- Old English Court repeatability;
- visitor-pilot review;
- live-provider agreement;
- governance approvals;
- measured unit economics.

Until these exist, the project must not invent:

- ROI;
- valuation;
- payback;
- round size;
- conversion of tourism volume into project revenue.

## 4. Regional / federal expansion room

Decision:

> after Moscow becomes decision-ready and a first external region passes the generic contract, agree the interregional proof and applicable regional/federal mechanism.

Package:

- Moscow-to-federal funding / scale playbook;
- investment-decision authority;
- architecture / integration;
- security / data-flow;
- IP / rights / handover;
- operations / SLA.

Current state:

**BLOCKED.**

Required external evidence:

- decision-ready Moscow result;
- first genuine external-region proof.

Federal framing:

> not “buy the Moscow app for all Russia”, but a regional connection standard + verified heritage infrastructure + journey/orchestration layer.

## Current commercial posture

The current strongest motion is:

1. show the consumer experience briefly;
2. run the guided 7–10 minute Government / Investor Route;
3. open Data Room;
4. demonstrate that executive and technical pilot packs are already prepared;
5. show that investment/federal stages are deliberately blocked by real-world proof;
6. close on one next decision: owner + pilot site + working session.

This makes the product easier to evaluate as a serious city partnership rather than as a concept demo.
