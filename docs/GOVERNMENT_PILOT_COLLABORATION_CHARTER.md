# Pilot Collaboration Charter

## Status

Proposed working model for the Moscow pilot.

This is not a pilot agreement, procurement document or contract.

Its purpose is to make the first collaboration motion operational:

`interest → owner/site → pre-pilot review → real evidence → final review → separate next-stage decision`.

## What the project team brings

- working CITY PILOT / consumer experience;
- PublishedSpatialPackage and City Heritage Studio authority;
- spatial / metric / field evidence contracts;
- Romanov field-test methodology;
- Old English Court repeatability intake;
- supervised visitor research pack;
- privacy-safe analytics;
- Live Destination provider/freshness/booking authority;
- buyer-facing technical / security / IP / operations drafts;
- Government Delivery Manifest, Funding Path and decision model.

## What Moscow / partners must provide

The project cannot fabricate these inputs in code:

- named city problem owner;
- pilot site and physical object access;
- heritage/content authority and experts;
- rights / publication / source-material input where required;
- integration/data owner for tourism-data / RUSSPASS / booking dialogue;
- permissions/rules for supervised visitor pilot;
- buyer-side IT/security/legal/procurement review;
- separate decision on the applicable pilot contract/support mechanism.

## Shared decisions

Before execution the parties must agree:

- bounded scope;
- acceptance evidence;
- data/provider authority;
- IP and handover boundaries;
- operations / incident / correction responsibilities;
- measured-economics outputs;
- who makes the final human Go / No-Go decision.

## Roles

### Project team

Owns implementation, product, platform contracts, evidence packaging and corrections.

Does not become historical, legal, procurement or budget authority.

### City problem owner

Owns the city problem, pilot boundary and stakeholder coordination.

Does not automatically equal final budget holder.

### Pilot operator / coordinator

Owns the applicable pilot procedure in its formal contour.

Participation does not automatically mean financial support or a future contract.

### Heritage / content authority

Owns historical review, sources, rights and object/content access.

Historical truth is not determined by the product team or commercial sponsor.

### Integration / data owner

Owns formal feed/sandbox/schema/freshness/attribution/booking semantics.

A public website or static register is not automatically live operational authority.

### Visitor research owner

Owns recruitment/consent outside app analytics and supervised-study discipline.

The first 20–50 participant study is usability/product evidence, not a representative Moscow population survey.

## Five gates

### Gate 1 — Scope / owner / site

Need:

- named owner;
- site;
- heritage contacts;
- integration contact;
- buyer-side reviewers.

Output:

- bounded pilot scope;
- RACI/contacts;
- external dependencies;
- technical working-session questions.

### Gate 2 — Pre-pilot approval

Need:

- technical specification;
- acceptance matrix;
- architecture/integration;
- security/data-flow;
- IP/handover;
- operations/SLA.

Repository/content readiness is not buyer approval.

The actual transition requires external review.

### Gate 3 — Evidence execution

Need real-world inputs:

- Romanov field day;
- Old English Court real asset/evidence/survey;
- 20–50 supervised visitor sessions;
- formal provider access or explicit integration result.

No missing proof can be closed by presentation, mock or manual green status.

### Gate 4 — Final evidence review

Need:

- final pilot report;
- acceptance results;
- governance review;
- measured cost / time / human-effort / operations inputs.

Output:

- proven / not proven / blocked matrix;
- measured unit economics;
- known operational risks;
- scale decision inputs.

### Gate 5 — Separate next-stage decision

Only after the evidence review can the relevant human decision makers choose:

- deployment / license / integration;
- investment review;
- first external region;
- re-scope;
- No-Go.

The pilot does not automatically convert into procurement, investment or federal funding.
