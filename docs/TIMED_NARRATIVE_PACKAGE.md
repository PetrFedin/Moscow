# Timed narrative package / WebVTT authority

Issue: #118.

Canonical source: `docs/MOSCOW_INTEGRATION_MASTER_PLAN_2026-10-01.md` → Audio/subtitle narrative package.

## Existing authority

Moscow already has a strong recorded-human-first audio contract:

- approved RU / EN / ZH scripts;
- human master gate;
- TTS fallback;
- narrator credit;
- rights evidence;
- binary SHA-256;
- measured duration;
- offline checksum verification;
- always-visible transcript.

This phase does not replace or duplicate that system.

## Goal

Add a verifiable timed-caption layer:

`approved transcript -> real human master -> timed cues -> measured sync evidence -> WebVTT -> captioned release`.

Until the full chain exists, the visitor keeps the existing transcript/TTS experience.

## Timed caption track

A caption track binds to:

- exact narration track ID;
- exact narration track version;
- locale;
- exact audio master SHA-256;
- exact measured audio duration;
- caption version;
- source reference;
- rights evidence;
- ordered timed cues.

Format authority is `webvtt`.

## Cue integrity

The release validator requires:

- unique cue IDs;
- integer millisecond boundaries;
- positive cue duration;
- no overlap/out-of-order cues;
- no cue beyond the real master duration;
- no reserved WebVTT arrow token inside cue text;
- normalized concatenated cue text equals the approved narration transcript.

Caption timing may split the script, but it may not silently rewrite it.

## Sync evidence

Timed text is not called synchronized merely because timings exist.

Measured evidence binds to the exact caption version + exact audio master checksum and records:

- evidence reference;
- reviewer;
- measured timestamp;
- number of sampled cues;
- p95 absolute timing drift;
- maximum absolute timing drift.

Current repository pilot thresholds:

- at least 5 sampled cues;
- p95 absolute drift <= 250 ms;
- max absolute drift <= 500 ms.

These are configurable pilot acceptance defaults, not external standards.

## Release states

- `captioned` — production human master + valid timed cue track + passing measured sync evidence.
- `transcript-only` — every other state.

Missing master, timings or evidence fails closed to transcript-only.

A TTS fallback never turns a timed-caption track into production synchronization authority.

## Current Varvarka state

No current Varvarka narration is promoted by this change.

The catalog remains recording-pending, so the user continues to receive:

- approved transcript;
- device TTS fallback;
- no false `captioned` claim.

After the real human masters return, timed cues and sync QA can be produced against their exact checksums/durations.

## WebVTT

`renderWebVtt(...)` produces deterministic WebVTT only after the timed-caption track validates against the exact production narration master.

No synthetic cue timings are generated by the repository.

## Next physical/editorial step

For each returned real narration master:

1. bind the exact SHA-256 and measured duration;
2. create human-reviewed cue timing;
3. verify full transcript parity;
4. measure cue drift against the master;
5. record sync evidence;
6. render/version WebVTT;
7. add the verified VTT asset to the offline route pack.

No step should be skipped merely to make the UI show captions.
