# «Москва во времени» — позиционирование пилота для городских структур

Дата: 2026-09-16

## 1. Почему нельзя продавать проект как «AR-экскурсию»

Москва уже развивает несколько близких цифровых направлений:

1. **«Узнай Москву»** — исторические объекты, периоды, прогулки и 3D-модели утраченных сооружений, которые используются в мобильных исторических маршрутах.
   - https://um.mos.ru/
   - пример публикации Дней исторического и культурного наследия: https://www.mos.ru/upload/documents/files/6655/MN_1_2025_SCREEN.pdf

2. **Московский транспорт в 3D** — транспортные объекты можно размещать в AR в натуральном или уменьшенном масштабе.
   - https://transport.mos.ru/3d_models

3. **«Экскурсии без остановок»** — исторические аудиомаршруты в автобусах, электробусах, трамваях, МЦД и на речном транспорте.
   - https://i.transport.mos.ru/road
   - https://i.transport.mos.ru/mcd-3
   - https://i.transport.mos.ru/river

4. **Музей Транспорта Москвы** создаёт цифровые двойники исторических экспонатов; 3D используется не только для public experience, но и как материал для будущих интерактивных экспозиций и реставрации.
   - https://transport.mos.ru/mostrans/all_news/128769

5. В 2026 году музей также заявляет крупную оцифровку фондов: тысячи книг, десятки тысяч листов документации и фотографии для будущих интерактивных проектов.
   - https://transport.mos.ru/mostrans/all_news/128328

Следовательно, ценность проекта должна быть не в факте наличия AR/3D/audio.

## 2. Правильный предмет предложения

### Digital Heritage Platform for Moscow

**Единый производственный и пользовательский контур для пространственной истории города.**

Один объект после подготовки получает:
- stable place id;
- исторические состояния;
- архивные источники;
- паспорт прав;
- documented/reconstructed/hypothesis classification;
- один versioned 3D model pack;
- field calibration;
- persistent spatial anchor;
- visitor story;
- audio/subtitles;
- 3D inspection mode;
- mobile AR;
- Quest VR;
- museum/browser preview;
- offline route package;
- analytics schema.

То есть город финансирует **не одноразовую AR-сцену**, а цифровой актив, который можно многократно использовать разными учреждениями.

## 3. Сильный пилот

### «Варварка во времени»

Объём:
- 5 точек исторической прогулки;
- 2 spatial hero objects;
- Палаты бояр Романовых — первый field-verified объект;
- Старый Английский двор — второй объект, подтверждающий повторяемость pipeline;
- минимум 2 исторических состояния hero object;
- Archive → 3D → AR → VR;
- RU/EN;
- audio;
- offline pack;
- accessibility;
- школьный сценарий;
- tourist scenario;
- source/reconstruction passport.

Пилот должен закончиться не презентацией, а повторяемым production standard для следующего района.

## 4. Что получает житель

### «Узнать место за минуту»

Пользователь не обязан идти на часовую экскурсию. Открывает приложение рядом с домом, метро или местом встречи и получает короткую историю в 30–60 секунд.

### «Тогда ↔ сейчас»

Архивный ракурс, старый план, реконструкция и современный вид связаны в одну временную линию.

### «Моя Москва»

Личная коллекция открытых мест, прогулок, эпох и тематических серий.

### «История по пути»

Не заставлять человека специально ехать на экскурсию. Исторический контент может сопровождать уже существующий путь: пешком, в трамвае, автобусе, МЦД или по реке.

### «Семейный архив»

Житель может предложить фотографию или историю места. Публикация — только после правовой и исторической модерации.

## 5. Что получает турист

- режим «рядом сейчас»;
- маршрут по доступному времени: 20 / 45 / 90 минут;
- RU/EN с архитектурной готовностью к дополнительным языкам;
- offline route pack;
- аудио, чтобы не идти постоянно с телефоном перед лицом;
- понятные обозначения факта и реконструкции;
- QR/NFC вход без поиска нужной карточки;
- 3D до посещения и VR после поездки;
- тематические прогулки, а не единый огромный каталог.

## 6. Что получает музей / архив

- один опубликованный источник может использоваться во многих маршрутах;
- IIIF или другой стабильный source contract вместо ручной пересылки изображений;
- 3D annotations;
- provenance;
- версия и история изменений;
- права видны до публикации;
- собственный контент учреждения остаётся атрибутирован;
- возможность сделать «музей без стен» вокруг городских объектов.

## 7. Что получает образование

### «Школьная Москва»

Не отдельная игра без учебной ценности, а curated packs:
- история Москвы;
- архитектура;
- литература;
- 1812 год;
- индустриализация;
- транспорт;
- конструктивизм;
- Великая Отечественная война — только на проверенной источниковой базе;
- история района школы.

Режим учителя:
- короткий маршрут;
- вопросы по точкам;
- источники;
- завершение класса без публичного рейтинга детей;
- материалы до и после экскурсии.

## 8. Accessibility как отдельная ценность

Пространственная история может сделать наследие доступнее, а не наоборот.

Пилот должен проверять:
- subtitles/transcript;
- audio description;
- большие размеры текста;
- high contrast;
- контент без обязательного AR;
- цифровое посещение помещений/точек, физически недоступных пользователю;
- маркировку доступности самого пешеходного маршрута.

Это важнее ещё одного визуального эффекта.

## 9. Цифровой паспорт наследия

На P2 один опубликованный public experience дополняется служебным preservation layer:
- geodetic control points;
- photogrammetry / mesh / point cloud references;
- модель текущего состояния;
- исторические model versions;
- состояния до/после реставрации;
- photo stations для повторной съёмки;
- provenance;
- review history.

Public historical reconstruction и служебная фиксация реального состояния хранятся раздельно, но связаны stable object id.

## 10. Интеграция с городским digital twin

Не пытаться заменить существующий «Цифровой двойник Москвы».

Потенциальная интеграция в будущем:
- stable object identifiers;
- координаты и пространственные границы;
- ссылка на published heritage package;
- current-state geometry reference;
- исторические состояния как отдельный temporal/cultural layer.

Digital Twin отвечает на вопрос **«что находится и происходит в городе сейчас / что изменится при планировании»**.

Moscow Time отвечает на вопрос **«как это место менялось, что из прошлого подтверждено источниками и как человек может пережить эти состояния в пространстве»**.

## 11. Participation without loss of trust

Из Project Tirtha стоит взять идею массового участия в документировании наследия, но не открывать прямую публикацию.

Сценарий «Снимок для истории»:
1. приложение показывает официальный контрольный ракурс;
2. житель повторяет фотографию;
3. система проверяет базовое качество/геометрию;
4. материал попадает в moderation queue;
5. после проверки становится частью временного ряда объекта;
6. авторство сохраняется;
7. использование в reconstruction требует отдельного provenance claim.

Это даёт городу распределённую repeat-photography сеть без превращения исторической базы в немодерируемую социальную сеть.

## 12. City Heritage Studio

Долгосрочный moat проекта — не сам viewer, а authoring pipeline.

Сотрудник музея/архива должен уметь без разработчика:
- выбрать объект;
- добавить историческое состояние;
- прикрепить источники;
- отметить права;
- привязать source → claim → model element;
- загрузить model version;
- расставить hotspots;
- добавить текст/audio/subtitles;
- собрать прогулку;
- отправить на историческую/правовую/техническую проверку;
- опубликовать immutable version.

Только после этого масштабирование на десятки районов становится экономически реалистичным.

## 13. Метрики, которые интересны городу

Не downloads и не количество GLB.

### Public value
- начатые и завершённые прогулки;
- число реально изученных объектов;
- повторное использование в течение 30 дней;
- доля коротких локальных сессий жителей;
- доля туристических маршрутов;
- usage accessibility modes;
- использование образовательных packs;
- переход audio → place → spatial experience.

### Content efficiency
- стоимость/срок публикации нового объекта;
- процент reuse одного asset между 3D/AR/VR/museum/education;
- доля источников, импортируемых стандартно без ручной обработки;
- число учреждений, способных самостоятельно подготовить draft package.

### Trust / preservation
- публичные элементы с provenance;
- unresolved rights;
- field-verified spatial scenes;
- число повторных photo stations;
- найденные расхождения/изменения объекта по годам.

## 14. Формула предложения

Не:

> «Мы сделаем приложение, где через AR можно посмотреть старую Москву».

А:

> **«Мы предлагаем на Варварке проверить городской стандарт цифрового исторического объекта: источники и права → проверенная реконструкция → единый 3D asset → полевая spatial verification → 3D/AR/VR/аудио/образование → измеримая эксплуатация. После пилота тот же pipeline можно передавать музеям и масштабировать на районы Москвы».**
