# Moscow — интеграционный стек MVP

## Цель

Использовать готовые, поддерживаемые SDK там, где они уже решают задачу, и тратить разработку на исторический контент, пространственную реконструкцию и пользовательский опыт.

## Выбранный стек

### 1. Карта Москвы — Yandex MapKit

**Статус: интегрируем сейчас.**

Почему:
- нативные iOS/Android карты;
- геопозиция;
- интерактивные маркеры;
- маршрутизация для пешехода, транспорта, велосипеда и самоката;
- поиск и геокодинг;
- панорамы;
- пользовательские raster tiles через UrlTile — пригодно для исторических карт;
- GeoJSON;
- офлайн-регионы доступны по платной лицензии MapKit.

В проекте используется `expo-yandex-mapkit` с full flavor. API-ключ не хранится в репозитории; он должен приходить из окружения либо конфигурации сборки.

### 2. AR + 3D + VR — ViroReact / ReactVision

**Статус: SDK подключён; первая сцена требует 3D-ассет и полевую калибровку.**

Поддерживает:
- ARKit на iOS;
- ARCore на Android;
- GLB/GLTF/OBJ/FBX;
- PBR, HDR, тени;
- image/object tracking;
- порталы;
- частицы и анимации;
- пространственный звук;
- cloud/geospatial anchors;
- Meta Quest / OpenXR;
- одна TypeScript-кодовая база для AR и VR.

Для первого этапа provider оставлен `none`: локальный AR работает без облачной привязки. После полевых тестов выбираем persistent anchor provider отдельно.

Важно: GPS-based geospatial anchors сами по себе дают точность порядка метров и недостаточны для точного совпадения исторического фасада. Для ключевых сцен нужен визуальный/cloud anchor либо контролируемая калибровка на месте.

### 3. Аудиогид

**Статус: доступно сейчас.**

- `expo-speech` — моментальная озвучка текста для прототипа RU/EN;
- `expo-audio` — воспроизведение профессионально записанной озвучки, фоновых звуков и скачанных аудиофайлов;
- ViroReact spatial audio — звук, привязанный к объектам внутри AR/VR сцены.

MVP: TTS как fallback + заранее записанный мастер-аудиогид для презентационного маршрута.

### 4. Офлайн

**Статус: интегрируем сейчас.**

- `expo-file-system` — загрузка и хранение изображений, аудио, 3D-моделей и route packs;
- `expo-sqlite` — локальная база объектов, эпох, прогресса и манифеста скачанных материалов;
- Yandex offline maps — отдельная платная лицензия; до неё приложение сохраняет контент офлайн, а карта требует сеть.

Офлайн-пакет маршрута должен включать контент, а не обещать офлайн-функции внешнего SDK без соответствующей лицензии.

### 5. Языки

**Статус: интегрируем сейчас.**

`expo-localization` определяет язык устройства. Контент хранится с отдельными RU/EN версиями. Переводы исторических фактов не должны выполняться на лету без редакционной проверки.

### 6. Исторические изображения

Используем несколько источников с различным режимом прав:

- Wikimedia Commons — предпочтительный источник для подтверждённого public-domain/свободно лицензированного контента;
- PastVu — сильный поисковый и географический источник, но права проверяются по каждому изображению; наличие снимка в PastVu не означает автоматического разрешения на коммерческое использование;
- официальные музейные и городские архивы — по отдельным соглашениям;
- собственное сканирование/public-domain коллекции — приоритетно для коммерческого MVP.

### 7. 3D-производство

Готового достоверного 3D-моделя исторического состояния Палат Романовых с подтверждёнными коммерческими правами пока нет.

Рабочий pipeline:
1. современная геометрия — фотограмметрия / обмеры;
2. историческое состояние — архивные планы, фотографии, исследования;
3. Blender — очистка, историческая реконструкция, LOD;
4. экспорт GLB;
5. mobile quality gate;
6. ViroReact — AR/VR/portal scene.

Фотограмметрия фиксирует современный объект; она не восстанавливает автоматически прошлое.

## Что не берём как базовый стек

### Unity
Не нужен в MVP как основной runtime. ViroReact уже покрывает необходимые мобильные AR/VR-сценарии и сохраняет TypeScript-кодовую базу. Unity остаётся резервом для сцен, которые действительно упрутся в ограничения ViroReact.

### Google ARCore Geospatial как единственная привязка
Не используем как единственный способ позиционирования до полевого подтверждения покрытия и точности на конкретных точках Варварки. Для фасада требуется более точный визуальный anchor/fiducial/calibration path.

### PastVu как CDN коммерческого контента
Не допускается автоматически: права на каждый снимок проверяются отдельно.

## Матрица MVP

| Возможность | Технология | Готовность |
|---|---|---|
| Карта Москвы | Yandex MapKit | SDK подключён, нужен API key |
| Геопозиция | Expo Location + MapKit | готово к разработке |
| Пешеходный маршрут | Yandex MapKit full | готово к разработке |
| Исторические слои карты | MapKit UrlTile/GeoJSON | готово при наличии тайлов |
| Тогда / сейчас | React Native UI | без внешней зависимости |
| Аудиогид | expo-speech / expo-audio | SDK подключён |
| Офлайн-контент | FileSystem + SQLite | SDK подключён |
| RU/EN | expo-localization | SDK подключён |
| 3D viewer | ViroReact GLB | SDK подключён, нужен GLB |
| AR | ViroReact ARKit/ARCore | SDK подключён, нужна сцена |
| Persistent visual anchors | ReactVision/ARCore provider | требует ключей и полевых тестов |
| VR episode | ViroReact + Meta Quest | поддерживается; нужен Quest app id и сцена |
| Spatial audio | ViroReact | поддерживается |
| Object recognition | Viro + optional ONNX package | не P0 |

## Ключевые внешние зависимости до полноценного пилота

1. Yandex MapKit Mobile SDK API key.
2. Выбор лицензии для офлайн-карт — только если офлайн-карта нужна уже в пилоте.
3. Первый оптимизированный GLB Палат Романовых.
4. Полевое обследование точки AR.
5. Решение по persistent anchors: ReactVision visual cloud anchors либо ARCore после проверки.
6. Meta App ID только когда включаем Quest build.
7. Реестр прав на каждую фотографию, аудио и 3D-ассет.

## Архитектурный принцип

Внешний SDK никогда не является источником исторической истины. Карта, AR runtime и аудио — только средства отображения. Исторический объект, его эпохи, источники, права, confidence и связи хранятся в нашей доменной модели Moscow.
