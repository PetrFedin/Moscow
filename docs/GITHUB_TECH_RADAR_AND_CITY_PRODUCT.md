# Москва во времени — GitHub Tech Radar и городской продукт

Дата актуализации: 2026-09-16

## 1. Архитектурный принцип

Главная техническая ставка проекта — не собирать отдельные демо под каждый носитель, а поддерживать один верифицированный исторический spatial asset и переиспользовать его в нескольких режимах:

`источники → модель/паспорт реконструкции → GLB model pack → 3D viewer → AR iOS/Android → VR Meta Quest → музейный/веб preview`

Для каждого состояния объекта модель разделяется по эпохе и уровню доказательности. Публичный интерфейс не должен скрывать неопределённость за фотореализмом.

## 2. Adopt — используем сейчас

### ReactVision / Viro

Repository: https://github.com/ReactVision/viro

Роль в Moscow:
- нативная 3D-сцена;
- GLB/GLTF runtime;
- ARKit / ARCore;
- hit test и локальные AR anchors;
- cloud/persistent anchors после полевого gate;
- один XR runtime для мобильного AR и Meta Quest/OpenXR;
- orbit camera и жесты для отдельного 3D inspection mode.

Решение: **оставить главным spatial runtime**. Он уже покрывает всю цепочку, поэтому второй 3D-движок на P0 создаст больше расхождений материалов, координат и QA, чем пользы.

### Google model-viewer

Repository: https://github.com/google/model-viewer

Роль:
- лёгкий browser preview GLB;
- быстрая проверка модели без запуска native build;
- демонстрационная и редакционная проверка model pack.

Это не основной runtime приложения и не замена AR/VR.

### Yandex MapKit

Роль:
- основная карта Москвы в российском пользовательском контуре;
- точки маршрута, геолокация, пешеходный сценарий.

Ключ хранится только в build environment. В Git не коммитится.

## 3. Watch — полезно, но не добавлять в P0

### Margelo react-native-filament

Repository: https://github.com/margelo/react-native-filament
License: MIT

Сильные стороны:
- высококачественный PBR 3D renderer для React Native;
- glTF/GLB;
- Metal/Vulkan/OpenGL через Filament.

Почему не добавляем сейчас: Viro уже является единым runtime для 3D/AR/Quest. Filament оправдан только если независимый 3D viewer позже окажется заметно лучше по качеству/производительности и его выигрыш перекроет стоимость второго renderer pipeline.

Gate для пересмотра: реальный benchmark одной Romanov GLB на целевых iPhone/Android.

### MapLibre React Native

Repository: https://github.com/maplibre/maplibre-react-native
License: MIT

Сильные стороны:
- vector tiles;
- собственные стили и исторические слои;
- Expo/React Native;
- потенциально больше контроля над offline/vector layer architecture.

Почему не меняем Yandex сейчас: пользователю нужен работающий московский маршрут, а не миграция картографического стека.

Использование в P1/P2: экспериментальный provider для исторических карт, собственных тайлов и специальных research/offline сборок.

### Smithsonian DPO Voyager

Repository: https://github.com/Smithsonian/dpo-voyager
License: Apache-2.0

Использовать как референс музейного 3D UX:
- 3D explorer;
- аннотации и точки интереса;
- представление научного/музейного контента вокруг модели;
- редакторский контур для сложных объектов.

Не заменяет Viro runtime; полезен прежде всего как образец организации 3D interpretation layer.

### CesiumJS / 3D Tiles

Repository: https://github.com/CesiumGS/cesium
License: Apache-2.0

Не нужен для одной Палаты Романовых. Нужен для будущего масштаба:
- квартал;
- исторические состояния городской территории;
- большие фотограмметрические datasets;
- 3D Tiles;
- связка с городским digital twin / GIS.

Статус: P2 research track, не P0 dependency.

## 4. Product references — переносим паттерны, не runtime

### Virtual Time Travel / museum4punkt0

Repositories:
- https://github.com/freies-deutsches-hochstift/virtual-time-travel
- https://github.com/museum4punkt0/virtual-time-travel
License: MIT

Полезные паттерны:
- городская история привязана к геокоординатам;
- QR как альтернативная точка входа;
- мобильная прогулка;
- контент можно конфигурировать музейной/культурной организацией.

Сам runtime устарел для нашего стека, поэтому код не переносим. Переносим продуктовую механику.

### HERA

Repository: https://github.com/liris-xr/HERA
License: GPL-3.0

Полезный паттерн: no-code/low-code authoring XR-сцен для организаций культуры.

Для Moscow это аргумент в пользу будущего **City Heritage Studio**, где музей/архив/редактор сможет собрать сцену из утверждённых моделей, источников, аудио и точек интереса без разработчика.

GPL-код не включать в закрываемый коммерческий runtime без отдельного лицензионного решения.

### Project Tirtha

Repository: https://github.com/project-tirtha/tirtha-public
License: AGPL-3.0

Полезный паттерн:
- жители фотографируют объекты наследия;
- система собирает материал для photogrammetry / Gaussian Splatting;
- создаётся открытый цифровой архив и 3D-реконструкция;
- один проект одновременно решает public engagement и preservation.

Для Москвы: будущая программа **«Снимок для истории»** / «Народный цифровой архив Москвы» с обязательной модерацией, правами и provenance.

AGPL-код не переносить напрямую в коммерческий runtime без отдельной лицензионной архитектуры.

## 5. Что является настоящим differentiator Moscow

Не «у нас есть AR». У Москвы уже существуют цифровые 3D/AR и аудиоэкскурсионные инициативы.

Differentiator должен звучать так:

> **Один исторически верифицированный spatial asset становится цифровым паспортом объекта и одновременно работает как 3D-модель для изучения, точно привязанная AR-сцена на месте, VR-сцена для удалённого посещения и музейный цифровой экспонат. У каждого слоя есть источники, права, уровень уверенности и полевая проверка точности.**

Дополнительное отличие — не отдельная акция, а платформа с повторяемым production pipeline для десятков и сотен объектов.

## 6. Пользовательский продукт для жителей и гостей

### P0 — то, что должно ощущаться как один продукт

1. **Рядом со мной** — исторические точки вокруг пользователя, не каталог на сотни карточек.
2. **60 секунд / 5 минут / глубже** — три уровня истории одного места.
3. **Тогда ↔ сейчас** — архивная фотография или историческая карта поверх современного вида.
4. **3D изучение** — объект можно вращать, приближать, выбирать эпоху и режим достоверности.
5. **AR на месте** — модель в реальном масштабе и правильной позиции после field verification.
6. **Прогулка** — 20/45/90 минут, прогресс и следующий объект.
7. **Аудиогид** — пользователь смотрит на город, а не всё время в экран.
8. **Офлайн-пакет маршрута** — тексты, изображения, аудио и 3D заранее.
9. **Моя Москва** — сохранённые находки, пройденные прогулки, коллекции.
10. **RU/EN + accessibility** — субтитры, transcript, большие размеры текста, audio description на ключевых сценах.

### P1 — городской сервис

1. **Школьная Москва** — маршруты по учебным темам, задания, режим учителя, верифицированные источники.
2. **Москва без барьеров** — доступные прогулки: физическая доступность маршрута + альтернативный цифровой просмотр недоступных пространств.
3. **Музеи без стен** — городской музей публикует объект один раз, а он появляется в маршруте, 3D, AR и VR.
4. **История по пути** — интеграция логики с существующими транспортными аудиомаршрутами: событие/объект открывается у нужной остановки или после выхода из транспорта.
5. **Семейный архив Москвы** — жители добавляют исторические фотографии и истории; публикация только после модерации и проверки прав.
6. **QR/NFC вход** — объект можно открыть из городской таблички, музея, выставки, школы или туристической навигации.
7. **Тематические сезоны** — 1812, конструктивизм, Москва 1940-х, исчезнувшие здания, транспорт, литературная Москва.

### P2 — городская цифровая инфраструктура наследия

1. **Digital Heritage Passport** — 3D/photogrammetry/model versions + история реставраций + источники + права + spatial calibration.
2. **City Heritage Studio** — редактор сцены для учреждений культуры без правки кода.
3. **Исторические кварталы** — стриминг 3D Tiles / крупномасштабных datasets, когда одного GLB уже недостаточно.
4. **Repeat photography** — жители и учреждения повторно снимают фиксированные контрольные ракурсы; можно видеть изменения фасада во времени.
5. **Field inspection layer** — служебный режим для сравнения зафиксированного состояния объекта по годам. Не смешивать с публичными художественными реконструкциями.
6. **Открытый API каталога** — только для опубликованных и лицензионно разрешённых метаданных/ассетов.

## 7. Что предлагать Правительству Москвы как пилот

### Пилот: «Варварка во времени»

Не обещать «AR всей Москвы».

Предмет пилота:
- 5 исторических точек Варварки/Зарядья;
- 2 истинно пространственных 3D-объекта;
- Палаты бояр Романовых — field-verified hero scene;
- минимум две эпохи одного объекта;
- archive → 3D → AR → VR;
- аудио и RU/EN;
- offline pack;
- source/reconstruction passport;
- школьный сценарий;
- туристический сценарий;
- accessibility сценарий;
- dashboard без персонального слежения: старты, завершения, глубина взаимодействия, возврат, drop-off по точкам.

### KPI пилота

Пользовательские:
- доля пользователей, дошедших до первого пространственного события;
- завершение прогулки;
- среднее число изученных объектов;
- переход archive → 3D → AR;
- сохранённые находки;
- повторный запуск/следующая прогулка;
- использование аудио/offline/accessibility.

Технологические:
- field residual по каждой контрольной точке;
- стабильность resolve persistent anchor;
- cold/warm load GLB;
- fps/thermal/memory на матрице устройств;
- recovery после ухода камеры/потери tracking;
- offline completeness.

Редакционные:
- 100% публичных элементов имеют provenance;
- права зафиксированы до публикации;
- hypothesis никогда не маскируется под documented geometry;
- история изменений источника/модели сохраняется.

## 8. Чего не делать

- не создавать второй native 3D-engine без benchmark-причины;
- не строить сразу весь город;
- не позиционировать AR как уникальность саму по себе;
- не смешивать digital twin для управления городом с художественной исторической реконструкцией;
- не импортировать GPL/AGPL-код в продукт без лицензионного решения;
- не выдавать GPS-привязку за точное фасадное совмещение;
- не делать экран главным объектом прогулки — аудио и короткие сцены должны возвращать внимание к самому городу;
- не собирать избыточные персональные данные ради аналитики.

## 9. Ближайшая инженерная последовательность

1. Romanov: закончить 3D inspection flow и связать `Archive → 3D → AR/VR`.
2. Варварка: реальные обмеры 5 контрольных точек и field matrix.
3. Persistent visual anchor: host/resolve на независимых iOS/Android.
4. После field PASS — зафиксировать первый `field-verified-spatial-scene`.
5. Второй объект: Старый Английский двор по тому же pipeline без новой архитектуры.
6. Затем route pack на 5 точек.
7. После двух spatial scenes — только тогда собирать городской пилотный пакет и масштабирование authoring pipeline.
