# Moscow — Execution Roadmap

**Date:** 2026-10-07  
**Authority:** `MOSCOW_END_TO_END_PRODUCT_BLUEPRINT_2026-10-07.md`

## Rule

Build by complete user loops, not by isolated dashboards.

## Wave 1 — Traveler core consolidation

1. Navigation -> Today / Explore / Trip / Wallet / My Moscow.
2. Move City Trip OS to product home.
3. Make Today the default returning-user surface.
4. Ensure 3-day trip creation.
5. Fixed/flexible timeline.
6. Commitment conflict engine.
7. Manual ticket/reservation import.
8. Wallet truth classes.
9. Adaptive replan.
10. My Moscow update after visit.

**Exit:** complete traveler golden path without external provider credentials.

## Wave 2 — Broad City Discovery & Event Engine

1. Canonical Place/Event schema.
2. Event timing and recurrence.
3. "open now / starts soon / fits window".
4. category taxonomy.
5. district taxonomy.
6. novelty/unvisited logic.
7. organic ranking.
8. transparent sponsored slot.
9. demo provider freshness.
10. event add-to-trip.

**Exit:** user can fill a real free window from a broad Moscow demo catalogue.
